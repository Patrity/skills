One doc-fetching skill plus six path-scoped rules. The rules fire when Claude touches .ts/.vue files under the app directory, anything under server/, or nuxt.config.ts, and tell it to consult the docs before guessing a composable signature or a config key.

What's inside

PathPurpose
skills/nuxt-docs/Fetches Nuxt 4 docs from GitHub by topic.
rules/web-nuxt.mdThe entry rule: invoke nuxt-docs first, Nuxt 4 layout, runtimeConfig for secrets.
rules/nuxt4.mdDirectory layout, aliases, auto-imports and component naming, route rules.
rules/ssr.mdSSR vs SPA, auth during SSR, hydration pitfalls, payload and prerender rules.
rules/backend.mdNitro routes: file-per-method, zod validation, createError shape.
rules/database.mdDrizzle + Postgres: migrations applied from CI, read-only roles for exploration.
rules/cli.mdScripts under scripts/ run through tsx: exit codes, dry-run first.
CLAUDE.mdA pointer block to paste into your project's CLAUDE.md.

Install

bash
  1. unzip nuxt.zip
  2. mkdir -p .claude
  3. cp -R nuxt/skills nuxt/rules .claude/
  4. cat nuxt/CLAUDE.md >> CLAUDE.md

The cache is disposable

The fetcher caches what it downloads under skills/nuxt-docs/cache/ for 24 hours. Delete it at any time; the next fetch rebuilds it.
